# 开发与实验验收规范

本文件规定各阶段应提供的可核对证据。通过软件测试只说明实现符合契约，不能替代数据质量审计。下面的测试均为待开发项目的验收要求；当前设计包不包含已运行的实验管线或测评结果。

## 核心风险测试

测试应使用可控的小型 fixture，覆盖成功、失败和边界路径。mock 样本要清楚标识，不需要真实新闻来验证恢复、缓存或抽样算法。

| 编号 | 风险与输入 | 预期行为及验收证据 |
|---|---|---|
| T01 | 原始数据集包含虚假文本或已有伪造图片；另外存在有完整操作日志的受控版本 | 原始版本仍按谱系记录 OT／OI；受控版本为 FT／FI。真实性和目标达成状态独立保存。未知制作历史不得由模型强行补齐。 |
| T02 | 六任务的输入中存在其他任务预测、基础标签或隐藏答案 | Prompt 构造器仅暴露该任务允许字段。断言实际请求中没有不允许的预测、答案、文件名提示或操作日志。候选感知 Reviewer 可见其被审候选，但这不改变标注任务的输入隔离。 |
| T03 | UNKNOWN 与实质标签共存；任务不适用；请求超时；无效 JSON | 非法标签集合被拒绝。经核验真实且现实错误机制归因不适用的样本进入跳过状态，不新增正常标签。技术失败保存为失败或可重试状态，不转换为 UNKNOWN。 |
| T04 | 模型引用不存在的证据 ID，或在来源不足时断言 EF／C1 | 证据 ID 校验能拒绝不存在引用；相应语义问题进入规则或 Reviewer 检查及必要人工处理，不能因 JSON 合法自动放行。单元测试证明路由契约，语义能力由人工审计评价。 |
| T05 | 同图、近重复、同事件、父子样本、多父组合及其 QA | 冻结划分不存在已知组级泄漏。多父样本不得跨 split 取材。输出可追溯的分组关系和冲突记录；仅样本 ID 不同不能作为独立性证据。 |
| T06 | 改变 Prompt、证据、图片内容、模型 revision、图像处理或被审候选 | 对应缓存键变化，旧结果不能复用。未改变输入的已完成任务可复用，日志能说明命中的是哪个版本。 |
| T07 | 任务完成后进程中断；重复提交人审文件；修订次数耗尽 | 重启后不重复写已完成记录，不重复运行已确认完成的调用；导入校验记录 ID 与版本。技术重试和语义修订各自有上限，耗尽后留下可审查状态，不能无限重试到通过。 |
| T08 | 单选题或多选题洗牌；重复选项；答案 ID 不存在；题干含答案线索 | 洗牌后的答案集合仍映射到正确稳定选项 ID；非法映射、重复选项及已知泄漏被拦截。答案唯一性、干扰项合理性和证据充分性继续交由 Reviewer 及人工核验。 |
| T09 | 已审核标签被人工更正，或证据和输入被更新 | 所有依赖旧版本的 QA 被标记失效，不能进入当前发布。重新审核后保留新旧版本和依赖关系，不静默替换。 |
| T10 | silver 标注被用于正式测试；一个任务的 gold 被传播到其他任务；只审标签未审 QA | gold 权限与记录级审核证据绑定。silver 不能自动升级 gold；未达到正式 QA 核验要求的题不能进入 gold test。 |
| T11 | 风险分层的抽样概率不同，且自动通过项存在已知错误 | 用总体分布已知的 fixture 验证抽样概率、权重与分母。结果分别包含错误检出、路由率和自动通过残余错误；不能只根据路由项估计总体漏检。 |
| T12 | 未解决、mock、过期 QA、许可缺失、未知答案引用或已知泄漏记录进入发布候选 | 发布检查明确阻止不合格条目进入要求更高质量等级的发布包，并输出具体失败原因。无效输出、拒答和技术失败进入运行报告，不从评测分母静默消失。 |

## 模型接入验收

模型接入须分别覆盖 Qwen3.8-27B 和 Gemma 4 31B。使用已提供的端点或已安装权重；未提供资源时保留未运行状态，不下载大权重或用其他模型替代。

1. **身份与版本**：记录可核对的模型仓库或本地来源、精确 revision、推理后端版本、精度／量化、processor、chat template 和图像处理配置。
2. **真实图像输入**：使用文本完全相同、图片明显不同的两条简单 fixture，检查图像确实进入请求且模型可观察到差异。仅 HTTP 200 或非空回答不算通过。
3. **结构化输出**：正常请求可解析且符合 schema；无效输出能进入设计好的有限修复或失败路径，不依赖未记录的人工复制粘贴。
4. **上下文独立**：每个任务为新会话；跨样本、跨任务和两个模型之间没有意外共享历史。Reviewer 默认模式标明 `candidate_aware`。
5. **成本与稳定性记录**：保存样本数、实际调用次数、耗时、错误与重试次数，并明确 token、显存或费用字段哪些可测、哪些尚未测得。
6. **功能边界**：未配置图像编辑工具时，系统不能声称已生成 FI。未配置证据源时不能编造外部核查结果。

smoke 通过只证明基本接入可用，不代表标注准确率、Reviewer 检出率或数据发布质量达标。

## 人工参考集与数据质量验收

### 独立性

应能核对人工首轮可见输入、标注手册版本、独立原始答案和仲裁记录。用于参考标签的盲审阶段不展示模型预测和其他标注员答案。日常修正中展示过模型意见的记录，应保留该事实，不能混同为独立盲审。

### 培训与一致性

完成手册讲解、两轮独立试标注、分歧讨论和必要的定义修订。按任务报告一致性、分歧和仲裁情况；不把一次综合平均分代替各任务边界是否清晰的判断。训练样本与正式独立审计样本分离。

### 抽检与估计

审计覆盖自动通过项及路由项，保留实际抽样概率和分层信息。对总体比例给出适合抽样设计的置信区间。按类别、数据来源、原始／受控条件等预设切片检查误差；样本不足的切片明确标记，不宣称达到稳定精度。

### 不确定与不适用

UNKNOWN 可以是有证据支持的正确判定；同时报告其比例及人工认可情况。任务不适用、技术失败和证据不足应按 schema 分别记录。没有足够证据形成确定答案时，不强制生成确定答案 QA。

### QA 人工核验

正式测试题应检查正确答案、单选唯一性或多选完整性、干扰项、题干清晰度、可见证据充分性及答案泄漏。来源两轴的题必须提供足够可观察信息，不考查只有制作日志才能知道、答题模型却看不到的制作历史。

不存在适用于所有任务的一套通用质量硬阈值。具体放行目标应在预实验后结合样本量、人工预算和使用场景确定并冻结；在未获得人工证据前，不能把设计目标写成已实现结果。

## 阶段验收

| 阶段 | 必需交付 | 可以进入下一阶段的条件 |
|---|---|---|
| M0 合同与 mock | 配置和 schema 加载、导入接口、mock fixture、SQLite 状态、版本及缓存机制、核心风险测试报告 | 不依赖 GPU 的关键契约已验证；未实现功能和缺少资源有清单；mock 无法混入正式发布。 |
| M1 模型 smoke | 两个固定模型的接入报告、版本锁定信息、真实图片请求记录、结构化结果、调用与错误统计 | 两个端点满足基本输入输出契约；未把 smoke 当作质量实验；资源与成本信息足以规划 pilot。 |
| M2 预实验 | 真实样本闭环、人工培训和参考集、逐任务质量及 Reviewer 评估、Prompt／手册修订记录、冻结的后续配置 | 主要标签边界可执行；主要失败模式已记录；质量目标有人工证据支撑，正式审计集未用于调参。 |
| 批量构建 | 可恢复运行 manifest、分组划分、已接受标注、QA、异常与人工队列、概率抽检结果 | 预先确定的质量门禁满足；修改导致的下游失效已处理；失败没有静默丢弃。 |
| 正式评测与发布 | gold test、数据卡、许可与谱系清单、质量报告、分任务基准、发布校验和版本记录 | 正式测试答案和 QA 满足人工核验要求；构建模型诊断与独立模型评测明确区分；已知泄漏及无效记录被拦截。 |

## 每轮开发结束时的报告格式

在 `docs/PROGRESS.md` 中记录：

- 本轮阶段与输入版本。
- 实际完成的功能和文件。
- 实际运行的测试、样本范围及结果。
- 未运行的检查与具体原因。
- 数据、模型或人工依赖中的真实阻塞项。
- 下一轮可以直接执行的任务。

涉及标签、schema、Prompt、分组或评测协议的变更，同时写入 `docs/CHANGELOG.md`，注明兼容性、需要重跑的阶段及失效的产物。开发日志应支持后续 Codex 从当前进度继续，而无需重新猜测哪些步骤已经运行。
