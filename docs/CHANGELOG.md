# 变更记录

## MMFakeBench VAL 与分层 TEST 数据制作

增加模型制作脚本和七标签导出。四个模型维度沿用 1.3.0。标签阶段支持冻结的分层 TEST 抽样，旧版前缀流程继续可用。各样本保留原始来源字段、模型审核元数据和可用标签列表。

## M2 单标签 Prompt 1.3.0

按英中修订稿新增独立英文版本和配置。四个任务明确预判和最终定标。标签审核独立复核线索，再判断标签与理由，并按现有三个审核决定路由。标注及审核建议的存档固定值由程序补齐。1.2.0 可继续用原配置运行。

## M2 单标签 Prompt 1.2.0

新增独立实验配置和英文任务卡。两个角色共享证据要求与各维度边界。四个模型维度强制单选并移除 `UNKNOWN`，现实语境新增 `PLAUSIBLE` 并进入常规审核。标签规范升为 2.0.0。旧记录包络字段继续可读，新标注要求 `applicability=applicable` 和 `unknown_reason=null`。说服策略的标签引导 QA 使用单选题。

基线继续使用原配置和渲染结果。新版使用独立批次与状态库。对照脚本先核对旧批次实际使用的样本 ID 和模型锁，再复制 val 导入记录及冻结划分。报告按样本、目标和任务匹配新旧结果。

## 1.0.0 2026 年 11 月 22 日

建立长期实验与开发合同：固定 Qwen3.8-27B Annotator、Gemma 4 31B IT Reviewer；定义六任务、来源谱系、独立 Prompt、标签引导 QA、人审与审计、版本和发布门禁。提供配置、结构、模板及合成夹具。尚无真实实验数据版本。

后续条目记录变化范围、兼容性、影响的已有运行、需要重新计算的缓存和需要失效的下游数据。

## M0 开发中

新增 Python 包、配置与合同校验入口、JSONL 导入、SQLite 租约与缓存、分阶段请求构造和脚本式 mock。研究配置、标签与 Schema 仍为 1.0.0。请求缓存键包含实际图像摘要、渲染 Prompt 与模型配置摘要。当前仅有本地开发和合成夹具运行，无既有正式数据需要迁移。

新增 `mock-run`，对已导入的合成快照顺序执行标注、标签审核、QA 生成与 QA 审核，并从 SQLite 读取已提交的阶段结果。缓存键纳入脚本响应和上下游依赖，技术与格式失败按各自额度重试。QA 准入使用本轮标签审核结果。

新增 `group` 和 `split`。分组涵盖素材哈希与谱系、多父样本、版本关系、QA 引用及外部确认的事件和近重复关系。冻结计划单独保存在 SQLite，可重跑相同计划。跨划分已知关系必须先解决才能生成计划。

新增 QA 选项洗牌和稳定答案映射，以及 `release --check-only` 候选快照检查。正式测试划分要求 gold。门禁会拒绝 mock、不可用状态、无明确媒体发布权限及已知跨划分关系。

新增 SQLite 版本退役与下游 STALE 事件。导入 supersedes_id 时在同一事务内使依赖旧内容哈希的任务失效。已有 SQLite 库自动创建失效表并保留历史结果。

新增 `export-snapshot`，按当前退役记录投影导入快照中标签、审核和 QA 的 STALE 状态。每个语义 ID 维持一条快照记录，语义哈希与 SQLite 中的原始导入内容保留。

`mock-run` 增加可选脚本 JSONL，按样本、主张和任务报告各阶段结果。默认仍可复用包内 QA 夹具执行四阶段 smoke。

`mock-run --provenance` 从已验证的样本来源记录生成文本和图像来源标签。受控制作记录绑定核验证据依赖，工作项可恢复并复用已提交的候选。

冻结划分接入 mock 运行与快照导出。工作项键纳入划分摘要，旧缓存会在首次采用冻结计划时重新计算。

mock 运行将合同格式的运行清单、标注、QA 与审核记录写入 SQLite 快照。导出追加本次运行的 mock 产物，保留候选的审核引用和上下游哈希。

新增 `audit --population` 与 `evaluate --population --selections --judgments` 的离线抽检与估计。总体文件使用 record_id、配置要求的分层字段和 routed_to_human。人工判定输入按 record_id 提供 annotation_error 与 needs_intervention 两个布尔值。

新增 `import-human`，将外部提供的人工记录按目标 ID、内容哈希和版本写入 SQLite。重跑相同提交幂等，冲突批次整体回滚。

快照可基于同版本确认式仲裁及配置规定的独立盲审人数生成 gold 状态，保留原语义 ID 与内容哈希。QA 还需要自身的审核依据和 gold 上游标签。

新增 `export-human`，导出盲审材料与匿名目标；QA 导入可按显示字母恢复稳定答案 ID。

纠正式仲裁在导入事务内创建 supersedes_id 关联的新版本并退役旧依赖。新版本清除旧审核引用，根据新仲裁和独立票数派生质量等级。

发布门禁汇总通过合同检查的快照中的质量和许可问题，包括已经识别为 mock 的快照。增加任务失败、人工路由和正式 test 拒绝用例。

QA 校验拒绝题干中的显式答案标记，规则接入生成阶段与快照合同检查。

新增 `evaluate-qa`。以固定快照中的合格题目为分母，分类统计错误选择、无效答案、超时、拒答、技术错误和缺失结果。

QA 生成与审核使用 QA 格式修复限额和通用格式限额中较小的一项。验收测试覆盖零次和一次修复，以及语义拒绝后的人工或排除路径。

原始 JSONL 导入明确要求相对于媒体根目录的图片路径。新增实际图片解码、来源字段和重复导入测试。

记录 CPython 3.9 本地验收环境的依赖版本及可复跑命令。

## 2026 年 11 月 23 日 MMFakeBench 数据适配

新增 `ingest --adapter mmfakebench`，支持官方 JSON 数组和解压后的图片目录。默认按原始真假与失真类别确定 2,000 条配额，并保留官方 test 划分。官方 val 映射到 dev。来源标签仅存溯源数据。真实样本使用标注文件 SHA-256 作为来源版本，导入同时将抽样清单写入 SQLite 新表 `import_manifests`。现有导入摘要算法、已冻结划分、Schema、标签、Prompt 和模型配置兼容。开发期间优先运行变更模块的独立测试，最终集中运行完整测试。

根据研究划分决定，将默认制作来源改为官方 val 全量，项目标记为 dev。官方 test 留作独立评测。默认规模从固定 2,000 条改为所选来源分区的全部唯一记录，显式 `--sample-size` 仍用于分层抽样。新制作批次使用 `mmfakebench-val` 作为 run ID。

新增 `generate-qa` 和 `review-qa`。QA Prompt 1.1.2 允许在材料不足时返回跳过原因。QA 批次复用已接受的真实标签和审核，独立冻结版本并追加阶段报告。SQLite 自动增加 QA 报告表。四个真实批处理命令的默认工作线程数改为 4，与 vLLM 的 `--max-num-seqs 4` 配合。

## vLLM 并发基准

部署命令的服务端并发上限改为 32。新增 `benchmark-vllm`，用相同的 val 标注请求对照各客户端并发档位。基准只读取导入快照，模型响应不进入数据集。正常批处理默认并发仍为 4。

并发基准支持 `--samples`，按实验种子固定选择 val 样本。默认 8 条，16 条试跑应使用完整 val 导入批次。

并发基准允许测试至 128 路，并支持按档重放 `--repeats`、本次 `--timeout-seconds` 及逐请求失败信息。

## M2 百条 val 标签基线

四个真实模型批处理命令的默认客户端并发改为 48。`annotate --offset` 支持在固定 val 顺序上分批，实际样本 ID 仍参与批次版本锁定。新增四批各 25 条的基线命令，独立执行标注和标签审核。现有 SQLite 库直接可用。在旧提交上开始的真实批次仍使用其原提交完成。

模型任务执行期间按 `heartbeat_seconds` 续租。租约确实丢失时，标签批次报告保留单条 `lease_lost` 失败及其余任务结果。提交声明 `Runtime-Resume-From` 后，可在该直接修复提交上续跑原标注批次或审核其候选。检查原父提交和改动范围，保留原批次与任务 ID，在阶段报告另记执行提交。现有 SQLite 无需迁移，成功结果按原任务 ID 复用。

百条 val 初标一次准备全部图文请求，四个预算分段共用一个客户端线程池。来源标签在模型阶段结束后生成。标注报告仍按原批次 ID 保存，可复用旧 SQLite 结果。合并报告记录准备、模型执行、来源标签三段耗时，以及预构造 HTTP 请求字节数。旧批次可以沿连续的纯运行时修复提交恢复。

来源标签的计算和校验在独立线程与模型推理并行，落库和报告合并在模型阶段后完成。`source_prepare_seconds` 记录可重叠的来源准备时间，`source_seconds` 记录模型阶段结束后的等待及落库时间。原来源任务 ID 和版本约束保持兼容。

真实标注在发送请求前用单个事务批量登记模型任务。已有记录保留原状态和 ID，新任务以 `QUEUED` 等待工作线程领租约。有效租约冲突记为单任务 `lease_busy`，其余模型任务继续，旧租约到期后可按原批次续跑。合并报告新增 `newly_registered` 和 `queue_seconds`。

`review-labels --batch-offsets` 读取原批次已验证的候选，先构造请求并批量登记，再用同一个请求池执行。保留单批入口、原审核任务 ID 和按批报告，增加包含准备、登记和推理用时的合并报告。SQLite 无需迁移。常规 vLLM 启动示例使用 64 个序列槽位，客户端默认 48 路并发。

`annotate` 与 `review-labels` 新增可选的 `--recover-timeouts`。各自返回前复用同一在线模型服务，用 360 秒客户端超时补跑终态超时并合并结果。历史补跑入口、配置、Schema、模型锁和任务 ID 继续兼容。

新增 `ingest --adapter mmfakebench --first-n` 冻结显式指定的官方 test JSON 前缀。`annotate` 和 `review-labels` 接受该前缀并保留 `split=test`，沿用同模型超时补跑和已有 Prompt、模型锁与 Schema。服务器脚本以独立本地状态库运行，在快照旁保存来源行号和与 val 的精确重合清单。既有 val 流程和抽样顺序保持兼容。
